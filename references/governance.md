# Activation, priority, and amendment

## Explicit activation

This skill remains inactive until the user names it or provides an equivalent explicit enablement instruction for a designated academic activity.

Task activation governs the named task. Conversation activation governs the named academic activity in the current conversation. Working-directory activation requires visible author-managed project guidance.

Recommended working-directory declaration:

```markdown
## Academic activity

For academic activities in this working directory, enable `$anti-slop-guard`.
Apply it only within academic tasks identified by the user.
```

## Priority

Within user-configurable work:

1. the user's current explicit instruction governs;
2. this skill governs other workflow skills and defaults;
3. other domain guidance remains advisory.

Platform constraints remain effective. State a blocking platform conflict directly in the visible conversation.

## User management

The user can add, remove, narrow, expand, or replace a rule. A clear user defect report establishes the defect for this workflow and authorizes correction of the affected rule.

Apply the correction visibly. Remove superseded behavior. Preserve no hidden fallback. Keep the repository free from hidden policy fields and silent activation state.

## Point-and-call governance

Point-and-call confirmation establishes shared understanding. It adds no approval loop when the author has already supplied a clear path.

After one visible objection, an author reiteration resolves that objection for a permitted action. Execute the reiterated path fully. State completion in the visible conversation.
