## Why

Academic AI assistance can introduce unrequested changes, hidden feedback, unnecessary validation, and accumulated text, code, figure, or operational debt. The project needs an explicitly activated skill that carries the author's stated intent into a bounded and visible execution workflow.

## What Changes

- Add an explicitly activated `anti-slop-guard` skill for designated academic activities.
- Establish author authority over problem definition, scope, scientific relationships, and final decisions.
- Separate visible conversational feedback from clean author artifacts.
- Add point-and-call confirmation for author-specified actions and paths.
- Add bounded rules for experimental data, code validation, figure ideation, and academic prose.
- Add user-governed maintenance when the author identifies a defect.
- Publish installation, activation, workspace-scoping, and contribution guidance in a README.

## Capabilities

### New Capabilities

- `user-sovereign-academic-guard`: Explicit activation, author-governed execution, visible feedback, scoped changes, and domain-specific academic guardrails.

### Modified Capabilities

None.

## Impact

The change adds a portable Codex skill, reference documentation, OpenSpec artifacts, project metadata, an MIT license, and public GitHub documentation. It adds no runtime dependency, background service, global hook, automatic trigger, hash index, or persistent activation mechanism.
